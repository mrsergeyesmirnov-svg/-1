# Закрытие личной смены: опрос на кассе iiko

Telegram **не** закрывает смену и **не** пишет человеку в личку «иди оцени».
Человек подходит к терминалу, вводит свой код, жмёт закрыть личную смену.
**До** окна с часами iiko показывает опрос. Без опроса смена не закрывается.

## Как это выглядит для сотрудника

1. Свой PIN на кассе (личные смены уже есть, общий кассир не используется).
2. Кнопка **закрыть личную смену**.
3. Окно опроса, два пункта:
   - как прошла смена (оценка 1–5);
   - что мешало работать (кухня / люди / организация / конфликт / нагрузка / гости / ничего).
4. **Готово** → Pulse принимает ответ → iiko закрывает смену → уже потом родное окно с часами.
5. Если опрос не прошёл или Pulse не отвечает — **смена остаётся открытой**.

На кассе не печатают длинный текст. Только оценка и причина.

## Что делает Telegram

Бот **не** просит писать в общий чат. Он ловит порог и шлёт **то же, что в 11:00 и 23:00**: короткий текст и кнопку-ссылку в личку.

Если за календарный день по залу **или** по кухне накопилось **больше трёх** плохих оценок (1 или 2), в чат зала или кухни уходит одно сообщение:

> Поймали, что на зале (кухне) что-то идёт не так — без имён.
> Расскажите подробнее в личке с ботом.
>
> [Рассказать в личке ❤️]

Кнопка открывает бота. Там пишут текст — в группу это не попадает. Повторно за тот же день и тот же цех бот не спамит.

Оценку на кассе уже сняли: в личке после этой кнопки сразу комментарий, не повторные звёзды. Обычные утренние/вечерние напоминания по расписанию не меняются.

## Лицензия разработчика плагинов — что это

Это **не** лицензия Pulse и **не** Windows. Это лицензия **iiko** на запуск чужого кода внутри iikoFront.

Две роли:

1. **Разработчик** (вы или интегратор). Пишет на `api@iiko.ru`, заключает договор, получает **ModuleId** — целое число, которым помечается плагин (`PluginLicenseModuleId` в коде и `LicenseModuleId` в `Manifest.xml`). Плюс лицензию разработчика, чтобы на тестовой кассе iikoFront **вообще загружал** плагины при отладке. Без неё DLL часто даже не стартует («нет цифровой подписи / нет лицензии»).
2. **Ресторан**. На боевых терминалах в лицензии iiko этой точки должен быть **тот же модуль**. Обычно это плата **за экземпляр**: 3 кассы = 3 слота. Плагин без модуля в лицензии точки iikoFront не поднимет.

Скелет `.cs` в репозитории **нельзя** положить в папку и ждать чуда. Нужна собранная **DLL** под версию API этой кассы (V7/V8/V9 — как у установленного iikoFront) и **ваш** ModuleId, не число из примера.

Частый путь: не становиться разработчиком самим, а отдать сборку интегратору, у которого лицензия и ModuleId уже есть.

Документация iiko: [лицензирование](https://iiko.github.io/front.api.doc/licensing.html), [папки](https://iiko.github.io/front.api.doc/directories.html).

## Как вставить плагин на кассу (Windows)

Скелет сейчас — исходник. На терминал кладут **результат сборки**.

1. Собрать в Visual Studio (.NET Framework 4.7.2) с ссылкой на `Resto.Front.Api.Vx.dll` **той же версии**, что у iikoFront на этой кассе. На выходе: `PulseShiftSurveyPlugin.dll`. Контракты iiko в папку плагина **не** копировать.
2. Закрыть iikoFront на этом компьютере.
3. Создать **новую подпапку** (один плагин — одна папка), не сваливать файлы в корень `Plugins`:

   `C:\Program Files\iiko\iikoRMS\Front.Net\Plugins\PulseShiftSurvey\`

   Если iiko ставили иначе, ищите папку `Front.Net\Plugins` рядом с самим iikoFront.
4. Внутрь этой папки:

   - `PulseShiftSurveyPlugin.dll` — собранный плагин
   - `Manifest.xml` — имя dll, класс, версия API, ModuleId
   - `plugin.json` — URL Pulse, ключ, guid организации, служебный PIN

   Не один «новый файл вместо всего», а **папка со своим комплектом**. Чужие плагины в соседних папках не трогать.
5. В `Manifest.xml` и в атрибуте C# — **один и тот же** ModuleId от iiko. `ApiVersion` = версия API кассы.
6. Запустить iikoFront. Плагин подхватывается при старте. Если лицензии модуля нет — в логах iikoFront отказ загрузки, кнопки не будет.

После этого на кассе появляется действие плагина «Закрыть личную смену»: опрос → Pulse → родное окно с часами. Пока DLL нет, в `Plugins` класть нечего.

## Людей по одному не собираем

Касса **уже знает**, кто ввёл PIN. Плагин берёт `employeeId` из текущей сессии и шлёт его в Pulse сам. Telegram-id и ручная таблица «Вася = uuid» **не нужны**.

Нужно один раз привязать **точку**, не людей:

```
/iiko_point <organizationId из iiko> <chat_id зала> [chat_id кухни]
```

`organizationId` — guid организации в iiko (один на точку). `chat_id` — из `/admin`.

### Выгрузка сотрудников — только если удобно, пачкой

Для закрытия смены справочник **не обязателен**. Он нужен лишь чтобы отличить зал от кухни, если плагин сам не пришлёт `department`.

В iiko это не ручной обход каждого человека:

1. **iikoOffice** → Персонал → Сотрудники → выгрузить в Excel.
2. Оставить три колонки: `id` (uuid/код), `фио`, `должность`.
3. Сохранить как CSV UTF-8 **или** скопировать таблицу.
4. В личке бота ответить на файл/текст командой `/iiko_import`.

Копипаст из Excel с табами тоже подходит. Telegram в этой таблице нет.

Если плагин шлёт `department` с кассы (роль в iiko: повар → кухня, иначе зал) — шаг с Excel можно не делать вообще.

## Что уже в Pulse (этот репозиторий)

| Часть | Статус |
|---|---|
| HTTP для кассы: опрос → permit → закрывать можно | **в коде** |
| Одна точка iiko → чаты Pulse (`/iiko_point`) | **в коде** |
| Пачка сотрудников из Excel (`/iiko_import`) | **в коде**, опционально |
| Анонимный дожим в чат после 3 плохих оценок | **в коде** |
| Плагин iikoFront на терминале (окно опроса + запрет закрытия без него) | **нужен C# на кассе** |

Без плагина Pulse умеет принять опрос и сказать «закрывать можно», но родная кнопка iiko окно не покажет. Замок живёт только в плагине.

### Переменные бота

```
IIKO_API_KEY=длинный-секрет
IIKO_HTTP_HOST=0.0.0.0
IIKO_HTTP_PORT=8091
```

Касса ходит на HTTPS этого API с заголовком `X-Iiko-Key`. Если ключа нет — HTTP выключен, закрывать через Pulse нельзя.

### API плагина

`GET /v1/iiko/survey-options`  
список оценок и причин (чтобы не хардкодить тексты в C#).

`POST /v1/iiko/shift-survey`  
тело:

```json
{
  "employeeId": "uuid-из-текущей-сессии",
  "organizationId": "guid-организации-iiko",
  "rating": 4,
  "blocker": "kitchen",
  "department": "hall"
}
```

Ответ `{ "ok": true, "closeShift": true }` — **только тогда** звать `ClosePersonalSession`.
Если Pulse недоступен, 401, 400 — **не закрывать**. Fail closed.

`GET /v1/iiko/clockout-permit?employeeId=`  
запасная проверка permit на сегодня.

`department`: `hall` или `kitchen`. Если не передать — Pulse смотрит выгрузку; если и её нет — считает залом.

Скелет плагина: `iiko_front_plugin/`.

## Плагин: порядок на кассе

iikoFront **не отдаёт** перехват родной «завершить работу» из Python. Делает это C#-плагин:

1. Кнопка плагина **«Закрыть личную смену»** (меню плагинов / замена привычного выхода).
2. WPF-окно: оценка + что мешало + «Готово».
3. `POST /v1/iiko/shift-survey`. Нет `closeShift: true` — отказ, смена открыта.
4. Есть разрешение → `ClosePersonalSession` → родное окно с часами iiko.

Чтобы не обойти опрос родной кнопкой, интегратор либо прячет стандартное закрытие, либо закрывает смену служебной учётки с правом `F_KIS` **только** после ответа Pulse.

Лицензия разработчика плагинов iiko — у интегратора (письмо на api@iiko.ru). Без ModuleId и лицензии на точке DLL не загрузится.

Документация iiko: [ClosePersonalSession](https://iiko.github.io/front.api.doc/2021/11/01/manage-others-personal-sessions.html), [SDK](https://github.com/iiko/front.api.sdk), [лицензия](https://iiko.github.io/front.api.doc/licensing.html).

## Чего нет и не будет в этом контуре

- QR в Telegram, `/start=out_`, «напиши боту чтобы уйти».
- Сбор iiko id и Telegram каждого человека вручную.
- Имена в рабочем чате.
- Длинный разбор души на кассе.
- Замок на Cloud clock-in курьеров вместо кассы зала.
