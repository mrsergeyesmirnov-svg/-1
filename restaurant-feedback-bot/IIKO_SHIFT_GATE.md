## Статус сборки

| Шаг | Что | Статус |
|---|---|---|
| **1** | Справочник Telegram ↔ iiko, permit после оценки, HTTP API, QR `/start=out_` | **в коде** |
| 2 | Неделя мягкого режима: «касса закрыта / отметки нет» (webhook iiko Cloud) | дальше |
| 3 | Pulse сам закрывает смену в Cloud после опроса | дальше |
| 4 | Плагин iikoFront — единственный замок на кассе | отдельно, C# |

### Шаг 1 — как включить

1. В iiko на точке — **личные смены** (свой PIN). Без этого шаг 4 бессмысленен; шаг 1 уже полезен как карта людей.
2. В `.env` бота: `IIKO_API_KEY=длинный-секрет` и опционально `IIKO_HTTP_PORT=8091`.
3. Админ в личке: `/iiko_link <telegram_id> <iiko_employee_id> <chat_id>` (5–10 человек пилота). `/myid` у сотрудника, chat_id в `/admin`.
4. Сотрудник оценивает смену в боте → Pulse пишет permit на сегодня.
5. Касса/плагин: `GET /v1/iiko/clockout-permit?employeeId=...` заголовок `X-Iiko-Key`.  
   QR на кассе: `POST /v1/iiko/whoami` `{"employeeId":"..."}` → `deepLink` в Telegram.

Пока плагина нет — это ещё не замок. Это фундамент: без карты людей шлюз слепой.

---

Задача: человек не может «уйти со смены» в системе, пока не рассказал о смене и о своём состоянии в боте.

Сейчас в Pulse отметка **добровольная**: напоминание в чат → кнопка в личку → звёзды. Чек-листы закрытия дня — только у **менеджера** и только блокируют пост в Telegram, не кассу.

---

## Сначала жёсткое ограничение реальности

**Заблокировать выход из здания нельзя и не нужно.** Блокируется **личная смена в iiko**: пока нет отметки Pulse, сотрудник формально ещё на смене (время идёт, менеджер видит).

Это сработает, только если в ресторане включены **личные смены** (у каждого свой пользователь / PIN в iikoFront). Если зал сидит под одним кассиром «Иван» — iiko не знает, кто ушёл. Тогда интеграция бессмысленна, пока не заведут личные учётки. Это главный фильтр пилота.

Анонимность отчётов сохраняется: в рабочем чате по-прежнему нет имён. Pulse внутри знает `telegram_id`, iiko знает `employee_id`. Связка нужна только шлюзу, не сводке для планёрки.

Личные факторы («усталость») лучше оставить **добровольными**. Обязательным сделать короткий факт смены: оценка + что мешало (10–20 сек). Иначе получите пять звёзд «отстаньте» и жалобу в трудовую.

## Три способа. Только один — настоящий замок

### 1. Мягкий (неделя, без плагина)

iiko умеет сказать «смена закрылась» (Cloud: `PersonalShift` webhook / опрос `employees/shift/is_open`; Front: событие закрытия сессии). Pulse **не останавливает** выход, а:

- пишет человеку в Telegram: «смена закрыта в iiko, отметки нет — 30 секунд»;
- если через N минут тишина — менеджеру в личку;
- в отчёте дня: «закрыли iiko / не отметились в Pulse».

Вовлечённость чуть вырастет. «Не мог не рассказать» — нет.

### 2. Pulse закрывает iiko (крепкий, без плагина на кассе)

Сотрудник **не жмёт «завершить работу» в кассе**. Он жмёт в боте «Уйти со смены» → опрос → Pulse вызывает iiko `ClosePersonalSession` / Cloud `employees/shift/clockout`.

Пока опроса нет — личная смена открыта.

Нужно:

- служебный пользователь iiko с правом принудительно закрывать чужие смены (`F_KIS`);
- карта: Telegram ↔ iiko employee id ↔ точка;
- договорённость в зале: «уход только через бота».

Дыра: дисциплинированный человек всё равно закроет смену пальцем на кассе, если плагин это не перехватит.

### 3. Плагин iikoFront (единственный замок на кассе)

Плагин на терминале (iikoFront API, C#):

1. Сотрудник жмёт «завершить работу».
2. Плагин **не вызывает** `ClosePersonalSession`.
3. Показывает QR / кнопку «Отметиться в Pulse» (deep-link в Telegram: `/start=out_{token}`).
4. Опрос в личке, 10–20 сек.
5. Pulse пишет `permit` в API: `{employeeId, shiftDay, ok: true}`.
6. Плагин поллит `GET /v1/iiko/clockout-permit?employeeId=` раз в 2 сек.
7. Получил ok → `ClosePersonalSession`. Не получил за 2 минуты → отказ, смена открыта, менеджеру алерт.

Это и есть «не уйдя со смены». Делается не в Python-боте, а отдельным плагином на каждую кассу + маленький HTTP API в Pulse.

Документация: [iikoFront Open/ClosePersonalSession](https://iiko.github.io/front.api.doc/2021/11/01/manage-others-personal-sessions.html).

## Что построить в Pulse (общий слой для 2 и 3)

1. **Справочник людей:** точка, `telegram_id`, `iiko_user_id`, роль (зал / кухня). Без этого шлюз слепой.
2. **Факт отметки за смену:** не «нажал 5 звёзд когда-то», а `permit(chat_id, business_date, employee_id)` после завершённого опроса (зал: rating; кухня: chef_shift).
3. **HTTP API** (только сервер плагина / служебный ключ, не публичный бот):
   - `POST /v1/iiko/whoami` — PIN/QR → telegram deep-link
   - `GET /v1/iiko/clockout-permit`
   - опционально `POST /v1/iiko/clockout` — сам закрыть сессию в Cloud
4. **Короткий сценарий «уход»:** отдельный `/start=out_…`, без лишних шагов, с явной фразой «после ответа закроем смену в iiko».

Связывать с чек-листом менеджера «закрытие дня» не надо: это другой контур (точка vs человек).

## Пилот на одной точке

1. Включить личные смены в iiko. Если «не заводим 20 PIN» — остановиться, делать только мягкий слой.
2. Связать 5–10 человек: Telegram + карточка iiko.
3. Неделя мягкого режима: цифры «закрыл кассу / ответил в боте».
4. Если дыра большая — плагин на одной кассе, не на сети.
5. Смотреть не «100% ответов», а **не мусор ли это**. Если средняя всегда 5.0 — замок работает, продукт нет.

---

## Чего не делать

- Не обещать интеграцию «как Казна с накладными». Накладные iiko ≠ личные смены.
- Не публиковать имена в рабочем чате.
- Не держать человека физически.
- Не делать обязательным длинный разбор души. Обязательна короткая отметка смены.
- Не вешать замок на Cloud clockin/out курьеров и думать, что зал закроется сам: у зала замок живёт в **iikoFront**.
