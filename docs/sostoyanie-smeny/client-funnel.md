# Воронка клиента «Состояние смены»

От первого касания до подписки на мониторинг.  
Проект Академии счастья. Не SaaS «купил бота», а траектория: боль → диагноз → изменение → удержание цифрой.

---

## Одна фраза

Собственник приходит с болью смены → вы даёте **диагноз и baseline** → чините 30/60/90 с человеком и ботом → показываете **было → стало** → оставляете **подписку**, чтобы результат не откатился.

Подписка — не старт воронки. Это **финал удачного проекта**.

---

## Схема целиком

```
Касание          Квалификация       Продажа проекта      Внедрение              Подписка
─────────        ────────────       ──────────────       ─────────              ────────
Боль / контент → Созвон / бриф   → Счёт на диагностику → Диагноз+baseline    → Мониторинг
сайт / TG / сарафан              КП / договор            Консалтинг 30/60/90     алерты
                                 (или пилот 14 дн.)      Контроль «было→стало»   ежемес. оплата
```

Методика внутри внедрения (этапы 01–08 с сайта):

| Этап методики | Где в воронке | Что платит клиент |
|---|---|---|
| 01 Знакомство | Квалификация | Пока ничего / время |
| 02 Диагностика | Проект начался | Часть проекта / отдельный счёт |
| 03 Выявление + **вкл. бот (baseline)** | Проект | Внутри проекта |
| 04 Решение | Проект | Внутри проекта |
| 05 Консалтинг | Проект | Основной объём часов |
| 06 Изменение 30/60/90 | Проект | Основной объём |
| 07 Контроль «было → стало» | Пред-подписка | Закрытие этапа / акт |
| 08 Мониторинг | **Подписка** | 2 990–8 990 ₽/мес с точки (+ подключение сети) |

Критично: бот включается на **выявлении**, не после «спасибо, до свидания». Иначе нечем доказать результат и нечего продлевать.

---

## Этап 0. До воронки — откуда приходит

**Кто:** собственник, гендир, УК сети (1–15 точек). Не линейный персонал.

**Откуда:**

- Telegram / сарафан / рекомендация ресторатора;
- сайт Академии → «Состояние смены»;
- тёплый контакт после боли (текучка, жалобы, «смена тяжёлая»);
- позже: выпускники туров / менеджеры по счастью.

**Боль на входе (язык клиента):**

- люди уходят;
- сервис пляшет;
- не понятно, что в команде;
- управляющий тушит пожары.

**Не продаём на первом экране:** «академию счастья» и «любовь». Продаём: **раннее обнаружение и чтобы смена не убивала людей**.

---

## Этап 1. Первое касание → квалификация

**Цель:** понять, ваш ли клиент и есть ли готовность меняться.

**Что делаете:**

1. Короткий созвон / переписка (15–30 мин).
2. Бриф: симптомы, сколько точек, кто ЛПР, что уже пробовали, готовность к цифре и к честности команды.
3. Фильтр «не ваш»: нет ЛПР, «просто бота поставьте», точка на выживании без бюджета, федерал с внутренним L&D.

**Выход с этапа:**

- да → диагностика / расчёт проекта;  
- нет → в базу тёплых или отказ честно;  
- «только бот» → пилот Pulse 14 дней **как исключение**, с явным ожиданием: без человека приживаемость ниже.

**Артефакт:** заметка в CRM / таблице: боль, точки, ЛПР, следующий шаг, дата.

---

## Этап 2. Продажа проекта (не подписки)

**Цель:** закрыть деньги на диагностику + контур изменений, не на «вечный SaaS».

**Что делаете:**

1. Аудит-калькулятор (часы × сложность) → вилка цены.
2. КП / созвон: путь 8 этапов, где включается бот, что будет через 30/60/90.
3. Договор / счёт: этапы, аванс, что входит в мониторинг после.

**Два нормальных оффера:**

| Оффер | Когда | Чем заканчивается |
|---|---|---|
| **Проект «Состояние смены»** | Основной путь | Диагноз → изменения → контроль → предложение подписки |
| **Пилот бота 14 дней** | «Хочу сначала цифру» | Либо вход в проект, либо платная подписка без большого консалтинга (слабее) |

**Выход:** оплаченный старт (аванс / счёт диагностики).  
Пока нет оплаты — это ещё не клиент воронки внедрения, это лид.

---

## Этап 3. Диагностика и baseline (здесь появляется «было»)

**Цель:** карта проблем + первая линия данных в боте.

**Что делаете:**

1. Диагностика по 4 блокам: люди / финансы / гость / процессы.
2. На этапе выявления — **подключаете Pulse** (чат, роли, напоминания, зал/кухня).
3. 1–2 недели собираете baseline: индекс смены, повторяющиеся факторы, дисциплина открытий.
4. Сессия с собственником: симптом → проблема → причина. Карта приоритетов.

**Что чувствует клиент:** «нас впервые измерили, а не только поговорили».

**Риск отвала:** бот подключен формально, линия не отвечает. Лечится внедрением с менеджером смены, не «ну вы напоминайте».

**Выход:** согласованная карта проблем + живой baseline + решение «что чиним первым».

---

## Этап 4. Консалтинг и изменение (30 / 60 / 90)

**Цель:** сдвинуть выбранные причины, не «провести тренинг».

**Что делаете:**

- сессии, обучение, практики коммуникации;
- менеджер по счастью / ответственные на точке;
- бот каждый день: сигнал → разбор на планёрке;
- контрольные точки 30 и 60 дней: те же метрики, что в baseline.

**Деньги:** основной объём проекта (по календарю актов / этапам).

**Выход на 60–90:** видимое «стало» по 1–2 KPI (текучка / индекс смены / жалобы — **один** главный, заранее выбранный).

---

## Этап 5. Контроль «было → стало» → оффер подписки

**Цель:** закрыть проект результатом и перевести в мониторинг.

**Что делаете:**

1. Отчёт: baseline vs сейчас по выбранному KPI + 4 блокам.
2. Что останется без вас (риски отката).
3. Оффер: **подписка «Состояние смены»** — алерты, сводки, дисциплина смен, сопровождение по тарифу.
4. Счёт на первый месяц / квартал мониторинга. Подключение сети — если ещё не закрыто в проекте.

**Почему клиент платит дальше:** боится потерять прозрачность и откатиться в «тушение пожаров». Не потому что «любит бота».

**Отказ от подписки — нормальный исход**, если:

- проект не дал цифры;
- бот так и не прижился;
- собственник купил только разовую «галочку для совести».

Тогда фиксируете кейс (или антикейс) и не давите. Подписка из насилия = churn через месяц.

---

## Этап 6. Подписка (финал воронки = начало LTV)

**Что входит в голову клиента:** «система мониторинга состояния смены».

**Ритм:**

- ежедневные/еженедельные сигналы;
- сводки управляющему;
- эскалации при просадке;
- раз в месяц — короткий контакт: «что горит, что делаем».

**Деньги:** MRR с точки (ориентир 2 990 / 6 990 / 8 990) + удержание.

**Успех подписки:** не «бот установлен», а **повторная оплата месяца 2 и 3** + линия реально отмечает смены.

**Расширение:**

- вторая точка сети;
- возврат в консалтинг, если индекс снова падает;
- люди точки → туры Академии (другая воронка).

## Две воронки, которые нельзя путать

### A. Основная (ваша сила)

`боль → проект → подписка`

Консалтинг продаёт смысл подписки. Подписка защищает результат.

### B. Короткая (слабее, но бывает)

`боль → пилот бота 14 дней → подписка или проект`

Имеет смысл, если ЛПР недоверчив к «консультантам». Риск: отключат через месяц без человека. Правило: пилот всегда с назначенным менеджером на точке и целью «войти в проект» или «осознанная подписка».

---

## Где воронка рвётся чаще всего

1. **После созвона** — нет следующего шага со счётом (висит «подумаю»).  
2. **После оплаты** — долгая диагностика без бота → клиент не видит «уже идёт».  
3. **Бот мёртвый** — нет baseline → нечего показать на контроле → нет подписки.  
4. **Красивый тренинг без KPI** — «спасибо», подписку не берут.  
5. **Подписка без ежемесячного смысла** — churn: платят за тишину.

## Метрики воронки (что завести в таблицу)

Считать просто, хоть в Google Sheet:

| Метрика | Зачем |
|---|---|
| Лиды / неделя | Вход |
| % до брифа | Качество касания |
| % брифов → оплата старта | Сила оффера |
| % проектов с живым baseline на 14-й день | Качество внедрения |
| % проектов → оффер подписки | Доводите ли до контроля |
| % офферов → оплата 1-го месяца | Сила «было→стало» |
| % подписок с оплатой 2-го месяца | Настоящий финал |

Финал воронки для бизнеса — не «подключили бота», а **вторая оплата подписки**.

---

## Что сказать клиенту одной дорожкой

> Сначала разберём, что ломает смену, и включим датчик — чтобы было «до».  
> Потом 30–90 дней чиним причины, а не симптомы.  
> В конце сравним «до» и «после».  
> Если хотите удержать результат — оставляете мониторинг по подписке. Без этого система снова слепнет.

Это и есть воронка от касания до подписки.
